🔷 layout - (plantilla)

En React (y en el desarrollo web en general), un layout (diseño o plantilla) es un componente estructurado que define la arquitectura visual y de navegación común para varias páginas o vistas de una aplicación.

Su objetivo principal es evitar la duplicación de código, asegurando que elementos estructurales fijos no tengan que reescribirse en cada pantalla individual. Es típico tener layouts para la parte pública y layouts para la parte de administración.

¿Qué elementos suele incluir un Layout?
Por lo general, un layout agrupa las partes de la interfaz que se mantienen estáticas mientras el usuario navega entre diferentes secciones:
- Barra de navegación superior (Navbar) o cabecera (Header).
- Menú lateral (Sidebar).
- Pie de página (Footer).
- Contenedores de contenido (áreas donde cambian dinámicamente las vistas).

🔷 lazy loading - (carga perezosa)

En el desarrollo web y en React, el lazy loading (o carga perezosa) es una técnica de optimización del rendimiento que consiste en retrasar la carga de recursos (como componentes, imágenes o datos) hasta el momento exacto en que el usuario realmente los necesita (por ejemplo, cuando aparecen en la pantalla o cuando hace clic en una ruta específica), en lugar de cargarlos todos al inicio de la aplicación.

¿Por qué es importante?
En una aplicación de React moderna, el código JavaScript suele empaquetarse en un solo archivo grande (o unos pocos archivos principales) utilizando herramientas como Vite o Webpack.
- Sin Lazy Loading: El navegador descarga todo el código de la aplicación de golpe antes de mostrarle la primera pantalla al usuario. Si la aplicación es grande, esto ralentiza el tiempo de carga inicial (Initial Page Load).
- Con Lazy Loading: La aplicación carga rápidamente mostrando solo lo esencial (como la página de inicio o el login) y descarga el resto de los componentes en segundo plano solo cuando el usuario navega hacia ellos.

¿Cómo se implementa en React?
React ofrece de forma nativa dos herramientas principales para lograr esto: React.lazy() y Suspense.
- 1. React.lazy()
Permite definir un componente que se cargará de forma dinámica mediante una importación dinámica de JavaScript (import()).
- 2. <Suspense>
Permite envolver los componentes perezosos y mostrar un contenido alternativo (un indicador de carga, como un spinner o un texto de "Cargando...") mientras el código del componente termina de descargarse de la red.

🔷 <Tabs> - Componente de la Librería Shadcn UI 

Tabs, TabsList y TabsTrigger (junto con Heart, que parece ser un icono de una librería como lucide-react) son componentes de React.
Forman parte de librería de interfaz de usuario (UI) del ecosistema de React, Shadcn UI, que utilizan componentes compuestos (compound components) para estructurar pestañas de navegación de manera accesible y estilizada.

Desglose de los componentes:

<Tabs>: Es el componente contenedor principal que gestiona el estado global de las pestañas (su atributo value='', cuál está activa actualmente).
- <TabsList>: Es el contenedor visual que agrupa y organiza la botonera o barra de pestañas (en este caso, configurado con una cuadrícula de 4 columnas mediante clases de Tailwind: grid w-full grid-cols-4).
- <TabsTrigger>: Es cada uno de los botones individuales dentro de la lista, que el usuario puede pulsar para cambiar entre las diferentes pestañas, identificadas con el atributo value='' (all, favorites, heroes, villains).

- <TabsContent>: Es la pieza que falta para que el sistema de pestañas funcione por completo.
En el patrón de diseño de Shadcn UI y Radix UI (componentes compuestos), cada vez que defines un TabsTrigger (el botón), necesitas su correspondiente TabsContent (el panel de contenido) para mostrar la información cuando esa pestaña esté activa.
¿Cómo se utiliza?
TabsContent recibe una prop value que debe coincidir exactamente con el value del TabsTrigger al que pertenece.

🔷 useLocation()

Es un hook muy útil que pertenece a React Router (la librería estándar para manejar la navegación y las rutas en aplicaciones de React).
Su función principal es darte información sobre la URL actual en la que se encuentra el usuario en ese momento.

¿Qué datos te devuelve?
Cuando ejecutas const location = useLocation(), obtienes un objeto que comúnmente contiene las siguientes propiedades:
- pathname: Es la ruta actual sin el dominio ni los parámetros de búsqueda (por ejemplo: "/productos" o "/contacto").
- search: Son los parámetros de búsqueda o query params que van después del signo de interrogación (por ejemplo: "?id=5&sort=asc").
- hash: El ancla o sección específica de la página que empieza con # (por ejemplo: "#seccion-2").
- state: Datos ocultos o información adicional que puedes enviar de una página a otra al navegar (muy útil para pasar datos sin que se vean en la URL).

Es especialmente útil para crear efectos visuales (como resaltar el enlace activo en una barra de navegación) o para disparar acciones cuando el usuario cambia de página.

🔷 Axios

En el ecosistema de React, Axios es una biblioteca de JavaScript muy popular que se utiliza para realizar peticiones HTTP (como GET, POST, PUT, DELETE) desde el navegador o desde un servidor (Node.js) hacia una API externa o un backend propio.

Funciona de manera muy similar a la API nativa del navegador fetch(), pero ofrece una serie de ventajas adicionales que facilitan el desarrollo.

Características Principales de Axios:

- Transformación automática de datos: Convierte automáticamente las respuestas recibidas (por ejemplo, desde una API REST) a formato JSON, ahorrándote el paso manual de hacer .json().
- Interceptores: Permite interceptar peticiones o respuestas antes de que sean manejadas por then o catch. Esto es ideal para añadir tokens de autenticación (como Bearer tokens) a todas las peticiones salientes o manejar errores globales de red.
- Protección contra XSRF: Ofrece soporte integrado para la protección contra ataques de falsificación de peticiones en sitios cruzados (XSRF).
- Cancelación de peticiones: Permite cancelar peticiones en curso (muy útil en React cuando un componente se desmonta antes de que termine una llamada asíncrona, previniendo fugas de memoria o errores de estado).
- Manejo de tiempos de espera (Timeouts): Facilita la configuración de límites de tiempo para las peticiones.

Requiere instalación con: npm i axios

🔷 Tanstack QUERY

https://tanstack.com/

TanStack Query (anteriormente conocido como React Query) es una de las librerías más potentes y populares para la gestión, almacenamiento en caché y sincronización de estado asíncrono en aplicaciones web.

Creada por Tanner Linsley, está diseñada para simplificar drásticamente la forma en que los desarrolladores manejan las peticiones a servidores (como llamadas a APIs mediante fetch o axios) y los resultados de las peticiones.

¿Qué problema resuelve?

Tradicionalmente, en frameworks como React, Vue o Solid, guardar los datos de una API requería usar estados locales (useState) y efectos (useEffect), junto con lógica manual para manejar:

- Estados de carga (loading).
- Manejo de errores (error).
- Reintentos automáticos si la petición falla.
- Actualización de datos obsoletos (stale data).
- Caché para no repetir peticiones innecesarias.

TanStack Query automatiza todo esto, permitiendo escribir código mucho más limpio, rápido y libre de bugs relacionados con la sincronización de datos remotos.

Características Principales:

- Caché inteligente: Almacena automáticamente las respuestas de tus peticiones. Si un componente vuelve a montar o necesita el mismo dato, lo sirve de inmediato desde la caché mientras busca una actualización en segundo plano (estrategia stale-while-revalidate).
- Sincronización automática: Puede actualizar los datos de la pantalla de forma automática bajo ciertas acciones, por ejemplo:
- Cuando la pestaña del navegador vuelve a estar activa (refetch on window focus).
- Cuando el dispositivo recupera la conexión a internet.
- A intervalos de tiempo configurables.
- Mutaciones simplificadas: Ofrece herramientas específicas para modificar datos en el servidor (crear, actualizar o borrar) y actualizar la caché automáticamente para reflejar los cambios al instante.
- Paginación y Infinite Scroll: Incluye hooks especializados para manejar listados largos, carga infinita y paginación de manera sencilla.
- Independencia de framework: Aunque nació asociado a React, hoy en día es multi-plataforma (TanStack), con adaptadores oficiales para React, Vue, Solid, Svelte y Angular.

-> 🔷 Tanstack Query DevTools 

Las TanStack Query Devtools (Herramientas de Desarrollo) son una interfaz visual flotante integrada en tu aplicación de React que te permite inspeccionar, monitorear y depurar en tiempo real todo lo relacionado con el estado del servidor gestionado por TanStack Query.
Funcionan de manera muy similar a las herramientas de desarrollo de Redux o a la pestaña "Network" del navegador, pero enfocadas exclusivamente en tus consultas (queries), mutaciones y la caché.

Qué puedes hacer con las Devtools?

- Inspeccionar la caché: Ver exactamente qué datos hay guardados en memoria, qué claves (queryKey) tienen asignadas y cuál es su estructura exacta en formato JSON.
- Monitorear el estado de las peticiones: Saber al instante si una consulta está activa (fetching), inactiva (inactive), obsoleta (stale) o si ha dado error.
- Control manual (Forzar acciones):
	- Forzar una actualización inmediata de los datos (Refetch).
	- Invalidar consultas de forma manual para ver cómo reacciona la interfaz.
	- Borrar datos de la caché (Reset / Remove) para probar estados iniciales o de carga.
- Depurar errores: Visualizar rápidamente por qué falló una petición HTTP y qué parámetros o reintentos se aplicaron.

¿Cómo se ven y se utilizan?

Normalmente se instalan como un paquete adicional y se colocan al final de tu árbol de componentes (por lo general, solo en modo de desarrollo). Tienen el siguiente aspecto en código:

- Instalar las Devtools de tanstack query: npm i @tanstack/react-query-devtools

	.

-> 🔷 useQuery()

Es el hook principal y más utilizado de TanStack Query en React. Su propósito fundamental es obtener, almacenar en caché, sincronizar y actualizar datos asíncronos (por lo general, mediante una petición HTTP GET a una API) dentro de un componente.

¿Qué hace exactamente?

Cuando llamas a useQuery dentro de un componente, este hook realiza las siguientes tareas de manera automática:
- Ejecuta la función de petición: Llama a la función que le pasas (la queryFn) para traer los datos del servidor.
- Administra los estados de carga y error: Te devuelve variables reactivas como isLoading, isError, data y error para que sepas en todo momento qué está pasando sin que tengas que crear estados manuales con useState.
- Almacena el resultado en caché: Guarda los datos obtenidos utilizando una clave única (queryKey). Si otro componente pide la misma información, se la entrega de inmediato sin volver a llamar a la API.
- Mantiene los datos sincronizados: Vuelve a buscar los datos en segundo plano bajo ciertas condiciones (como cuando el usuario cambia de pestaña y regresa) para asegurar que la información no esté desactualizada.

¿Cómo se estructura?

useQuery recibe un objeto de configuración que requiere obligatoriamente dos propiedades principales:
- queryKey: Un array único que identifica la consulta. TanStack Query usa esta clave para gestionar la caché, invalidar datos y saber qué peticiones están asociadas entre sí (ej. ['usuarios'] o ['usuario', id]).
- queryFn: Una función que devuelve una promesa (por lo general usando fetch o Axios) encargada de ir a buscar los datos al servidor.
- staleTime: (tiempo de obsolescencia) Define durante cuánto tiempo (ms) los datos obtenidos se consideran "frescos" (fresh) y se mantienen en caché, en la dirección marcada por la queryKey. Esto permite no tener que hacer la misma petición http durante el tiempo establecido. 
Por defecto, TanStack Query considera que los datos se vuelven obsoletos (stale) inmediatamente (staleTime: 0) en cuanto se descargan.

Qué te devuelve?

El hook devuelve un objeto con múltiples propiedades muy útiles. Las más comunes son:
- data: Los datos devuelven por el servidor (si la petición fue exitosa).
- isLoading: true si es la primera vez que se cargan los datos y aún no hay nada en caché.
- isFetching: true cada vez que se está haciendo una petición al servidor (incluso en segundo plano actualizando la caché).
- isError: true si ocurrió un fallo.
- error: El objeto de error detallado.

🔷 useNavigate() - react-router hook

En React, useNavigate es un hook introducido en React Router (a partir de la versión 6) que sirve para navegar de forma imperativa entre las diferentes rutas de una aplicación (es decir, cambiar de página o vista mediante código, como respuesta a una acción del usuario).

Antes de la versión 6, esto se hacía principalmente con el componente <Redirect> o usando el objeto history pasado por las props. Hoy en día, useNavigate es el estándar moderno y recomendado.

useNavigate devuelve exactamente una función (que comúnmente llamamos navigate).
Esta función es la que ejecutas posteriormente para cambiar de ruta y acepta dos parámetros:
- to: Puede ser un string con la ruta de destino (ej. '/dashboard', '/perfil') o un número para moverse en el historial (ej. -1 para retroceder).
- options (opcional): Un objeto con configuraciones adicionales como { replace: true } o { state: { ... } }.

¿Para qué sirve? (Casos de uso principales)

Se utiliza cuando necesitas redirigir al usuario a otra ruta tras un evento o condición, por ejemplo:
- Tras enviar un formulario: Una vez que el usuario hace login o registra un producto con éxito, lo envías al dashboard o al inicio.
- Botones de "Volver atrás" o "Siguiente": Controlar el historial de navegación de forma personalizada.
- Validaciones de acceso: Si un usuario no está autenticado, lo rediriges automáticamente a la pantalla de inicio de sesión.

¿Cómo se usa? (Ejemplo práctico)

Para usarlo, debes estar dentro de un componente que esté envuelto por un <BrowserRouter> (o cualquier otro router de React Router).

Opciones y funcionalidades avanzadas

El hook navigate que te devuelve la función acepta dos argumentos principales: navigate(to, options)

Navegar hacia adelante o atrás en el historial:
- Puedes pasarle números enteros en lugar de una ruta, imitando los botones del navegador:
	navigate(1) avanza una página.
	navigate(-1) retrocede una página (equivale al botón "Atrás").
	navigate(-2) retrocede dos páginas.

- Reemplazar la ruta actual (replace):
Si no quieres que la página actual se guarde en el historial del navegador (útil para que el usuario no pueda volver atrás con la flecha del navegador, por ejemplo, tras hacer logout):
	navigate('/login', { replace: true });

- Enviar datos (State):
Puedes pasar información oculta a la siguiente ruta a través de la propiedad state:
	navigate('/perfil', { state: { usuarioId: 123 } });
(Luego puedes recuperar estos datos en la página de destino usando el hook useLocation).

🔷 useParams() - react-router hook

useParams() es un Hook de raact-router que permite acceder a los parámetros dinámicos de la URL actual.

¿Qué es?
Es una función proporcionada por React Router que conecta tus componentes con la estructura de la ruta actual sin necesidad de pasar props de forma manual desde el componente principal.

¿Qué retorna?
Retorna un objeto JavaScript que contiene los pares de clave-valor de los parámetros dinámicos definidos en la ruta.
- Las claves corresponden a los nombres que definiste con dos puntos : en el path de la ruta.
- Los valores son los datos reales que vienen en la URL en ese momento. (Nota: los valores devueltos son siempre de tipo string).

¿Para qué se usa?
Se utiliza principalmente para crear rutas dinámicas y renderizar contenido personalizado según el parámetro de la URL.
Casos de uso comunes:
- Mostrar el perfil de un usuario específico (/perfil/:username).
- Cargar los detalles de un producto o artículo de blog (/productos/:id).
- Obtener identificadores para realizar peticiones a una API (fetch/axios) dentro de un useEffect.

🔷 URL query parameters - parámetros de búsqueda de la URL

La parte que va después del signo de interrogación ? en la URL de la página.

Las URL query parameters (también conocidos como parámetros de consulta o parámetros GET) son un conjunto de opciones o datos adicionales que se envían al servidor a través de la URL.

Se colocan al final de la dirección web, después de un signo de interrogación (?) son strings, y se utilizan para filtrar, ordenar, buscar o configurar la información que se muestra en la página sin necesidad de cambiar de ruta principal.

Estructura de una URL con Query Parameters
Una URL con parámetros sigue una estructura estricta:

	https://misitio.com/productos?categoria=ropa&orden=precio-asc&pagina=2

Desglose de los elementos:
- Ruta base: [https://misitio.com/productos](https://misitio.com/productos) (Indica la página o recurso general).
- Signo de interrogación (?): Actúa como separador entre la ruta y los parámetros de consulta.
- Pares de clave-valor: categoria=ropa (La clave es categoria y su valor es ropa).
- Amperson (&): Se utiliza para separar múltiples parámetros cuando hay más de uno.

¿Para qué se utilizan?
Son sumamente comunes en el desarrollo web para:
- Filtros y ordenamiento: ?precio=bajo&color=azul (en tiendas online).
- Búsquedas: ?q=react+router (en buscadores como Google o barras de búsqueda internas).
- Paginación: ?page=3 o ?limit=10 (para saber qué lote de datos mostrar).
- Identificadores de marketing o seguimiento: ?utm_source=newsletter&utm_medium=email (para saber de dónde viene el tráfico).

Características clave:
- No alteran la ruta principal: /productos sigue siendo la misma página base; los parámetros solo ajustan el contenido interno.
- Son legibles por el usuario y el navegador: Se pueden copiar, pegar y compartir fácilmente para replicar exactamente el mismo estado visual de la página (por ejemplo, mandar un enlace de un producto filtrado a un amigo).
- ⚠️ Son públicos: Como viajan directamente en la barra de direcciones del navegador, nunca deben usarse para enviar información sensible o privada como contraseñas o números de tarjetas de crédito.
- ⚠️ Son opcionales, pueden venir o no en la URL, por lo tanto pueden ser null.
Por esta razón, en el código siempre se deben manejar valores por defecto (fallbacks) usando operadores lógicos como el operador de cortocircuito (||) o el encadenamiento opcional.
Si visitas /productos (sin parámetros), terminoBusqueda será null, pero gracias al || '', tu código no fallará y simplemente mostrará el texto vacío en lugar de la palabra "null" en pantalla.

🔷 useSearchParams() - react-router hook

useSearchParams() es otro Hook de react-router fundamental, pero a diferencia de useParams() (que lee los parámetros dinámicos de la ruta), este se usa para leer y modificar los parámetros de búsqueda (query parameters) de la URL (la parte que va después del signo de interrogación ?).

¿Qué es?
Es un Hook diseñado para interactuar con la cadena de consulta (query string) de la URL actual, similar a cómo funciona useState pero sincronizado directamente con la barra de direcciones del navegador.

¿Qué retorna?
Retorna un array de dos elementos (muy similar a la estructura de useState):
- searchParams: Un objeto de la clase URLSearchParams que contiene los parámetros actuales de la URL y métodos para leerlos.
Ejemplo sobre la url http://localhost:5173/?nombre=pepe , par obtener el nombre: searchParams.get('nombre').
- setSearchParams: Una función para actualizar o cambiar los parámetros de búsqueda, lo cual actualiza automáticamente la URL sin recargar la página.

¿Para qué se usa?
Se utiliza comúnmente para manejar estados que deben reflejarse en la URL y ser compartidos o guardados fácilmente, tales como:
- Filtros y ordenamiento en listados de productos (ej. ?categoria=zapatos&orden=precio-asc).
- Sistemas de paginación (ej. ?pagina=2).
- Términos de búsqueda en una barra de búsqueda (ej. ?q=react).

Si el usuario escribe "laptop" en una búsqueda, la URL cambiará dinámicamente a /tu-ruta?q=laptop, permitiendo que si copian y pegan ese enlace, la página cargue directamente con la misma búsqueda activa.

En este proyecto, la forma de pedir la paginación la determina el backend.

Cuando se dice en el desarrollo frontend (con React o cualquier otro framework) que la forma de paginación la determina el backend, significa que es el servidor (la API) el que define cómo, cuánta y bajo qué reglas se divide y se entrega la información, y el frontend debe adaptarse estricta y pasivamente a esas reglas para mostrarla.

Para entenderlo mejor, conviene repasar los dos grandes enfoques de paginación:

1. Paginación por el Backend (Server-Side Pagination)
El backend tiene el control absoluto de la base de datos y de la lógica de negocio. Cuando el usuario en tu aplicación de React cambia de página o hace scroll, tu código en React le pide al backend solo un fragmento específico de los datos (por ejemplo, "dame los registros del 11 al 20").

El backend determina aspectos clave como:

- El mecanismo de petición: Puede exigir parámetros de tipo Offset/Limit (ejemplo: ?offset=10&limit=10), de tipo Page/PerPage (ejemplo: ?page=2&per_page=10), o de tipo Cursor (ideal para infinite scroll, donde pides los elementos anteriores o posteriores a un ID específico).

- El tamaño del bloque: El backend decide si te manda bloques de 10, 20 o 50 elementos por defecto, y a veces ni siquiera te permite cambiarlo desde el frontend.

- La estructura de la respuesta: El JSON que devuelve el servidor no es solo un arreglo de datos ([...]), sino un objeto contenedor que incluye metadatos definidos por él, tales como:

JSON
{
  "data": [...],
  "totalItems": 150,
  "totalPages": 15,
  "currentPage": 2,
  "hasNextPage": true
}

2. ¿Qué pasaría si la determinara el frontend? (Client-Side Pagination)
Para contrastar, en la paginación por el frontend, el servidor te entrega absolutamente todos los datos de golpe (por ejemplo, los 1,000 registros de una tabla) en una sola petición HTTP.

En este escenario alternativo, React guarda todo ese array gigantesco en su estado local y es el componente de React el que se encarga de recortar el arreglo (array.slice()) según la página en la que esté el usuario.
